# План смены CDN/хостинга для PainHelp

## Текущая проблема

Ссылка:

```text
https://quiz.painhelp.ru/1st-pain-quiz-styled.html?quiz=pain-v1&skip_cover=yes
```

Без VPN иногда наблюдается большая задержка еще до появления заставки `Загружаем квиз…`.

Проверка показала:

- DNS и TLS обычно устанавливаются быстро;
- первый байт от Vercel приходит быстро;
- иногда передача HTML зависает до таймаута;
- проблема возникает до запуска JavaScript, поэтому код заставки не может ее устранить;
- текущий домен `quiz.painhelp.ru` обслуживается через Vercel;
- прямой адрес `painhelp.vercel.app` также использует Vercel и не гарантирует обход проблемы.

## Что уже сделано в коде

В `1st-pain-quiz-styled.html`:

- Google Fonts убраны из критического пути загрузки;
- заставка загрузки активна сразу в статическом HTML;
- добавлен preload сценария;
- добавлен таймаут загрузки JSON;
- добавлен локальный кэш сценария;
- при проблемах с сетью используется ранее загруженный сценарий.

В `vercel.json` подготовлены заголовки кэширования для HTML и сценариев JSON, но публичная версия пока показывает старый заголовок `cache-control: public, max-age=0, must-revalidate`, если изменения не закоммичены и не задеплоены.

## Рекомендуемая архитектура

```text
quiz.painhelp.ru  -> Cloudflare Pages
api.painhelp.ru   -> текущий backend или Cloudflare Functions
```

Статические файлы квиза и сценарии должны отдаваться через CDN. CRM-запросы должны оставаться на backend или быть отдельно перенесены в serverless functions.

## Что необходимо для переноса

1. Доступ к DNS-зоне домена `painhelp.ru`.
2. Выбрать новый хостинг: рекомендуется Cloudflare Pages; альтернативы — Netlify или GitHub Pages.
3. Подключить GitHub-репозиторий `rkowalyov/painhelp` к новому хостингу.
4. Настроить публикацию статических файлов из корня репозитория.
5. Подключить `quiz.painhelp.ru` к новому проекту.
6. Настроить HTTPS-сертификат.
7. Решить, где будет работать backend API:
   - оставить текущий `server.js`;
   - использовать отдельный backend-домен `api.painhelp.ru`;
   - перенести API в Cloudflare Functions или Netlify Functions.
8. Перенести переменные окружения:

```text
BITRIX_WEBHOOK
BITRIX_CONFIRM_WEBHOOK
ALLOWED_ORIGINS
```

9. Обновить CORS, если API будет размещен на другом домене.
10. Проверить работу без VPN.

## Важное ограничение

GitHub Pages подходит для HTML/CSS/JS/JSON, но не запускает `server.js` и API. Поэтому при выборе GitHub Pages backend нужно оставить отдельно.

## План проверки после переноса

- открыть основной URL без VPN;
- проверить, что заставка появляется сразу;
- проверить загрузку `scenarios/pain-v1.json`;
- проверить параметр `?quiz=pain-v1`;
- проверить параметр `&skip_cover=yes`;
- проверить редактор `quiz-editor`;
- проверить отправку лида в Bitrix24;
- проверить подтверждение лида;
- проверить CORS и HTTPS;
- сравнить время первого байта и полное время загрузки.

## Состояние на паузе

Перенос пока не выполняется. Изменения в коде локальные; коммит и деплой для этой задачи не выполнялись.

Когда можно будет вернуться к вопросу, начать с выбора между Cloudflare Pages и Netlify, затем определить место размещения API и после этого менять DNS.
