# Quiz Editor — Документация

**Визуальный конструктор JSON-квизов для Bitrix24**

---

## Назначение

Quiz Editor — браузерное приложение без backend-зависимостей. Оно позволяет:

- создавать вопросы и варианты ответов,
- задавать итоговый скоринг,
- привязывать каждый вопрос к `UF_CRM_...` полю лида,
- настраивать диагностические флаги,
- видеть предварительный просмотр интерфейса,
- экспортировать готовый JSON для сценария.

## Каноническая схема CRM-полей

В редакторе и в активном сценарии используется единый финальный список полей:

```json
"crm_fields": {
  "score": "UF_CRM_1777993552",
  "result": "UF_CRM_1777993608",
  "is_chronic": "UF_CRM_1777993788",
  "failed_treatment": "UF_CRM_1777993848",
  "source": "UF_CRM_1777993881",
  "answers_json": "UF_CRM_1786729063"
}
```

### Важные правила

- `result` хранит человекочитаемый итоговый текст результата, а не `low/medium/high` в сыром виде.
- `answers_json` — единственное поле для JSON ответов пользовательского прохождения.

## Архитектура редактора

### Состояние (`app.js`)

Редактор держит состояние в памяти и синхронизирует его с DOM-формами. Основные этапы:

```text
questions[] → renderAllQuestions() → DOM → buildJson() → export JSON
```

### Основные части интерфейса

- **Мета** — заголовок, кнопка старта, email-экран, `source_label`
- **Вопросы** — добавление, удаление, сортировка вопросов и вариантов
- **Скоринг** — пороги, заголовки, тексты, CTA
- **CRM-поля** — поля лида в Bitrix24
- **Предпросмотр** — симулятор прохождения квиза
- **Превью JSON** — итоговый объект для вставки в сценарий

---

## Флаги CRM

### `chronic_if_gte_index`

Активирует флаг `is_chronic`, если пользователь выбрал вариант с индексом, равным или большим `chronic_threshold`.

### `failed_treatment_if_value`

Активирует флаг `failed_treatment`, если значение выбранного ответа совпадает с `failed_treatment_value`.

---

## Скоринг

Итоговый score рассчитывается по сумме `score` всех ответов пользователя.

```text
totalScore = sum(score)
```

Далее выбирается уровень результата по максимальным границам блока `scoring`.

Важно:
- `crm_fields.score` это число;
- `crm_fields.result` это строка итогового текста результата;
- `result` нельзя путать с raw id уровня категории.

## Предпросмотр и экспорт

### Предпросмотр

Вкладка Preview показывает, как проходит квиз с точки зрения пользователя. Она не отправляет данные в CRM.

### Экспорт

Кнопка экспорта собирает актуальное состояние редактора и сохраняет JSON в формате, подходящем для файлов в [scenarios](scenarios).

---

## Автосохранение

Редактор сохраняет состояние в `localStorage` автоматически, чтобы не терять данные между сессиями.

## Интеграция с обработчиком квиза

Запуск сценария осуществляется через URL:

```text
?quiz=pain-v1_growth_2608_001
```

Параметр `quiz` выбирает JSON-файл из [scenarios](scenarios). Внутри файла хранится и вся логика, и CRM-мэппинг.

## Финальный список полей для Bitrix24

Используйте только этот список:

- `UF_CRM_1777993552` → score
- `UF_CRM_1777993608` → result
- `UF_CRM_1777993788` → is_chronic
- `UF_CRM_1777993848` → failed_treatment
- `UF_CRM_1777993881` → source
- `UF_CRM_1786729063` → answers_json

Это единый согласованный набор, который должен быть одинаковым в сценариях, редакторе и CRM-логике.

https://painhelp.vercel.app/1st-pain-quiz-styled.html?quiz=pain-v1&edit=Y
```

**Процесс:**
1. Обработчик загружает JSON из `scenarios/pain-v1.json`
2. Параметр `&edit=Y` активирует режим редактирования
3. Автоматический редирект на Quiz Editor с предзаполненными данными
4. Редактируйте квиз в интерфейсе редактора
5. После изменений: **Экспорт JSON** → замените старый файл → пушьте в GitHub

### Формат передачи данных в Битрикс24

Обработчик квиза вызывает `crm.lead.add` со следующими полями:

```js
{
  fields: {
    // Стандартные поля лида
    NAME:       "Имя",
    LAST_NAME:  "Фамилия",
    SECOND_NAME:"Отчество",
    EMAIL:      [{ VALUE: "user@example.com", VALUE_TYPE: "WORK" }],
    PHONE:      [{ VALUE: "+7...", VALUE_TYPE: "WORK" }],

    // Метаданные
    [crm_fields.source]: meta.source_label,

    // Результаты скоринга
    [crm_fields.score]:  totalScore,
    [crm_fields.result]: "low" | "medium" | "high",

    // Флаги (если сработали)
    [crm_fields.is_chronic]:       true | false,
    [crm_fields.failed_treatment]: true | false,

    // Ответы на вопросы
    [questions[0].crm_field]: "выбранный value",
    [questions[1].crm_field]: "выбранный value",
    // ...
  }
}
```

### Подключение к странице Битрикс24 Сайты

1. В редакторе страниц Битрикс24 добавить блок «HTML/JS»
2. Вставить тег `<script src="quiz-handler.js"></script>` (или inline-код обработчика)
3. Убедиться что `quiz.json` доступен по относительному пути от страницы
4. Опубликовать страницу

## Зависимости

### Runtime (CDN, без установки)

| Ресурс | Назначение | URL |
|--------|-----------|-----|
| General Sans | Основной шрифт (тело) | `api.fontshare.com` |
| Cabinet Grotesk | Заголовочный шрифт | `api.fontshare.com` |

Все остальное — **нативный браузерный JavaScript (ES2020+)**, без npm, без сборщиков, без фреймворков.

### Браузерные API

| API | Использование |
|-----|---------------|
| `localStorage` | Автосохранение состояния редактора |
| `HTML5 Drag and Drop API` | Сортировка вопросов и вариантов |
| `navigator.clipboard` | Копирование JSON в буфер |
| `FileReader` | Загрузка JSON-файла |
| `<template>` element | Шаблоны карточек вопросов и строк вариантов |
| `URL.createObjectURL` | Скачивание JSON-файла |

### Совместимость браузеров

Все используемые API поддерживаются в актуальных версиях Chrome, Firefox, Safari, Edge (2020+).  
`localStorage` недоступен в `<iframe>` c `sandbox` без атрибута `allow-same-origin`.

## Деплой и хостинг

Редактор — полностью статический сайт (3 файла). Может быть размещён на любом хостинге:

### Вариант 1: pplx.app (текущий)
```
https://quiz-editor.pplx.app
```

### Вариант 2: Локальный запуск
```bash
# Любой статический сервер, например:
npx serve /path/to/quiz-editor
# или
python3 -m http.server 8080 --directory /path/to/quiz-editor
```
Открыть `http://localhost:8080`

> Прямое открытие `index.html` через `file://` работает для редактирования, но `localStorage` может быть ограничен в некоторых браузерах.

### Вариант 3: Любой статический хостинг
Загрузить `index.html`, `style.css`, `app.js` в корень — редактор заработает немедленно.
