## Назначение

Quiz Editor — браузерное одностраничное приложение (SPA) без backend-зависимостей. Позволяет без написания кода:

- создавать квизы с произвольными вопросами и вариантами ответов
- настраивать скоринговую систему (три уровня результатов по сумме баллов)
- привязывать каждый вопрос к пользовательскому полю лида в Битрикс24 (`UF_CRM_...`)
- задавать флаги для специальных условий (`is_chronic`, `failed_treatment`)
- экспортировать готовый `quiz.json` совместимый с существующим обработчиком квиза
- предварительно просматривать квиз в режиме симулятора без отправки данных

## Схема JSON-квиза

Редактор производит и потребляет JSON следующей структуры:

```json
{
  "meta": {
    "title":          "Заголовок квиза",
    "subtitle":       "Подзаголовок",
    "trust_badges":   ["Без регистрации", "Анонимно"],
    "cta_start":      "Пройти тест",
    "webhook":        "https://xxx.bitrix24.ru/rest/1/<token>/crm.lead.add",
    "source_label":   "Тест Квиз 26_05_07",
    "email_title":    "Мы почти готовы показать результат",
    "email_subtitle": "Оставьте email...",
    "email_fear":     "Fear-фраза перед отправкой"
  },

  "questions": [
    {
      "id":         "question_id",          // slug, уникальный в рамках квиза
      "crm_field":  "UF_CRM_1234567890",    // ID поля лида в Битрикс24
      "text":       "Текст вопроса?",
      "flag":       "chronic_if_gte_index", // необязательно, см. раздел «Флаги»
      "chronic_threshold": 2,               // параметр флага chronic_if_gte_index
      "options": [
        { "label": "Вариант А", "value": "a", "score": 0 },
        { "label": "Вариант Б", "value": "b", "score": 2 }
      ]
    }
  ],

  "scoring": {
    "low":    { "max": 3,  "title": "...", "text": "...", "cta": ["Кнопка 1", "Кнопка 2"] },
    "medium": { "max": 7,  "title": "...", "text": "...", "cta": ["..."] },
    "high":   { "max": 99, "title": "...", "text": "...", "cta": ["..."] }
  },

  "crm_fields": {
    "score":            "UF_CRM_...",  // итоговый балл
    "result":           "UF_CRM_...",  // текстовый результат (low/medium/high)
    "is_chronic":       "UF_CRM_...",  // флаг хронической боли
    "failed_treatment": "UF_CRM_...",  // флаг неудачного лечения
    "source":           "UF_CRM_..."   // метка источника квиза
  }
}
```

### Поля лида в Битрикс24

Стандартные поля лида (имя, фамилия, отчество, email, телефон) передаются обработчиком напрямую через `crm.lead.add` — в JSON квиза их описывать не нужно.

## Архитектура редактора

### Состояние (`app.js`)

Весь редактор работает с единым массивом `questions[]` в памяти. Форма мета-данных, скоринга и CRM-полей хранится непосредственно в DOM (поля `<input>`/`<textarea>`).

```
questions[]  ←→  DOM (renderAllQuestions / syncDomToState)
     ↓
  buildJson()  →  quiz.json
```

**Ключевые функции:**

| Функция              | Назначение |
|----------------------|------------|
| `loadFromObject(data)` | Загружает квиз из объекта в DOM и `questions[]` |
| `buildJson()`          | Собирает актуальный JSON из DOM + `questions[]` |
| `syncDomToState()`     | Читает DOM вопросов в `questions[]` (перед сортировкой, экспортом) |
| `renderAllQuestions()` | Полностью перерисовывает список вопросов из `questions[]` |
| `renderQuestion(idx)`  | Рендерит одну карточку вопроса с обработчиками |
| `addOptionRow(container, qIdx, oIdx, opt)` | Добавляет строку варианта ответа |
| `initQuestionDnD()`    | Инициализирует drag-and-drop для карточек вопросов |
| `saveToStorage()`      | Сохраняет `buildJson()` в `localStorage` |
| `loadFromStorage()`    | Восстанавливает JSON из `localStorage` |

### Вкладки редактора

| Вкладка        | Что редактируется |
|----------------|-------------------|
| **Мета**       | Заголовок, вебхук, trust-badges, email-экран, source_label |
| **Вопросы**    | Список вопросов, варианты ответов, CRM-поля, флаги |
| **Скоринг**    | Три уровня результатов: пороги баллов, заголовки, тексты, CTA |
| **CRM-поля**   | Глобальные поля лида: балл, результат, флаги, источник |
| **Предпросмотр** | Интерактивный симулятор квиза |
| **Превью JSON** | Итоговый JSON с возможностью копирования/скачивания |

## Флаги CRM

Флаги — специальные булевы поля лида, которые проставляются автоматически по условиям из ответов.

### `chronic_if_gte_index`

Ставит `is_chronic = true`, если **индекс** выбранного варианта ≥ `chronic_threshold`.

```json
{
  "flag": "chronic_if_gte_index",
  "chronic_threshold": 2,
  "options": [
    { "label": "Несколько дней",    "value": "short",   "score": 0 },  // индекс 0
    { "label": "Несколько недель",  "value": "weeks",   "score": 1 },  // индекс 1
    { "label": "Несколько месяцев", "value": "months",  "score": 2 },  // индекс 2 → флаг
    { "label": "Более 6 месяцев",   "value": "chronic", "score": 4 }   // индекс 3 → флаг
  ]
}
```

### `failed_treatment_if_value`

Ставит `failed_treatment = true`, если `value` выбранного варианта совпадает с `failed_treatment_value`.

```json
{
  "flag": "failed_treatment_if_value",
  "failed_treatment_value": "no_result",
  "options": [
    { "label": "Нет",                        "value": "no",        "score": 2 },
    { "label": "Да, но лечение не помогло",  "value": "no_result", "score": 3 }, // → флаг
    { "label": "Да, сейчас прохожу лечение", "value": "treatment", "score": 1 }
  ]
}
```

## Скоринг

Результат определ��ется суммой `score` по всем ответам пользователя.

```
totalScore = sum(answers[i].score)

if totalScore <= scoring.low.max    → уровень "low"
if totalScore <= scoring.medium.max → уровень "medium"
else                                → уровень "high"
```

Уровень `high.max` обычно ставится в `99` — это означает «всё что выше medium».

**Что передаётся в лид:**
- `crm_fields.score` ← числовой балл
- `crm_fields.result` ← строка `"low"` / `"medium"` / `"high"`

## Предпросмотр квиза

Вкладка **Предпросмотр** рендерит интерактивный симулятор в формате мобильного экрана (375px). Данные в CRM не отправляются.

**Экраны симулятора:**

1. **Стартовый** — заголовок, подзаголовок, trust-badges, кнопка старта
2. **Вопрос** — прогресс-бар, текст вопроса, кнопки вариантов. После выбора — автопереход через 320ms
3. **Email-экран** — имя, фамилия, отчество, email, телефон, fear-фраза
4. **Результат** — балл в цветном кружке (зелёный/жёлтый/красный), заголовок из скоринга, текст, CTA-кнопки, активные флаги

Симулятор **всегда берёт актуальное состояние** редактора в момент переключения на вкладку.

## Автосохранение

Редактор автоматически сохраняет состояние в `localStorage` под ключом `quiz_editor_state`.

- **Триггер:** любое `input`, `change` или `click` внутри области редактора
- **Задержка:** 800ms после последнего события (debounce)
- **Индикатор:** «✓ Сохранено» в шапке появляется на 2 секунды
- **Восстановление:** при следующем открытии страницы данные загружаются автоматически
- **Сброс:** кнопка «Сброс» в шапке очищает `localStorage` и загружает демо-квиз

> ⚠️ `localStorage` недоступен внутри `<iframe>` по политике браузера. Автосохранение работает только на [quiz-editor.pplx.app](https://quiz-editor.pplx.app) или при запуске файлов локально.

## Интеграция с обработчиком квиза

### Создание нового квиза

1. Открыть Quiz Editor (локально или на хостинге)
2. На вкладке **Мета** заполнить:
   - URL вебхука Битрикс24 (`crm.lead.add`)
   - `source_label` — уникальная метка для фильтрации в CRM
3. На вкладке **CRM-поля** указать ID пользовательских полей лида
4. На вкладке **Вопросы** создать вопросы, для каждого:
   - Задать уникальный `id` (slug без пробелов)
   - Указать `UF_CRM_...` поле для сохранения ответа
   - Добавить варианты с `label`, `value` (slug) и `score` (балл 0–99)
   - При необходимости выбрать флаг и его параметр
5. На вкладке **Скоринг** настроить пороги и тексты результатов
6. Перейти на **Предпросмотр** и пройти квиз целиком
7. **Экспорт JSON** → «Скачать quiz.json»
8. Поместить `quiz.json` в папку `scenarios/` и коммитить в GitHub

### Редактирование существующего квиза

Открыть URL вида:
```
https://quiz.painhelp.ru/1st-pain-quiz-styled.html?quiz=pain-v1&edit=Y
```

**Процесс:**
1. Обработчик загружает JSON из `scenarios/pain-v1.json`
2. Параметр `&edit=Y` активирует режим редактирования
3. Автоматический редирект на Quiz Editor с предзаполненными данными
4. Редактируйте квиз в интерфейсе редактора
5. После изменений: **Экспорт JSON** → замените старый файл → пушьте в GitHub

### Формат передачи данных в Битрикс24

Обработчик квиза вызывает `crm.lead.add` со следующими полями:

```js
{
  fields: {
    // Стандартные поля лида
    NAME:       "Имя",
    LAST_NAME:  "Фамилия",
    SECOND_NAME:"Отчество",
    EMAIL:      [{ VALUE: "user@example.com", VALUE_TYPE: "WORK" }],
    PHONE:      [{ VALUE: "+7...", VALUE_TYPE: "WORK" }],

    // Метаданные
    [crm_fields.source]: meta.source_label,

    // Результаты скоринга
    [crm_fields.score]:  totalScore,
    [crm_fields.result]: "low" | "medium" | "high",

    // Флаги (если сработали)
    [crm_fields.is_chronic]:       true | false,
    [crm_fields.failed_treatment]: true | false,

    // Ответы на вопросы
    [questions[0].crm_field]: "выбранный value",
    [questions[1].crm_field]: "выбранный value",
    // ...
  }
}
```

### Подключение к странице Битрикс24 Сайты

1. В редакторе страниц Битрикс24 добавить блок «HTML/JS»
2. Вставить тег `<script src="quiz-handler.js"></script>` (или inline-код обработчика)
3. Убедиться что `quiz.json` доступен по относительному пути от страницы
4. Опубликовать страницу

## Зависимости

### Runtime (CDN, без установки)

| Ресурс | Назначение | URL |
|--------|-----------|-----|
| General Sans | Основной шрифт (тело) | `api.fontshare.com` |
| Cabinet Grotesk | Заголовочный шрифт | `api.fontshare.com` |

Все остальное — **нативный браузерный JavaScript (ES2020+)**, без npm, без сборщиков, без фреймворков.

### Браузерные API

| API | Использование |
|-----|---------------|
| `localStorage` | Автосохранение состояния редактора |
| `HTML5 Drag and Drop API` | Сортировка вопросов и вариантов |
| `navigator.clipboard` | Копирование JSON в буфер |
| `FileReader` | Загрузка JSON-файла |
| `<template>` element | Шаблоны карточек вопросов и строк вариантов |
| `URL.createObjectURL` | Скачивание JSON-файла |

### Совместимость браузеров

Все используемые API поддерживаются в актуальных версиях Chrome, Firefox, Safari, Edge (2020+).  
`localStorage` недоступен в `<iframe>` c `sandbox` без атрибута `allow-same-origin`.

## Деплой и хостинг

Редактор — полностью статический сайт (3 файла). Может быть размещён на любом хостинге:

### Вариант 1: pplx.app (текущий)
```
https://quiz-editor.pplx.app
```

### Вариант 2: Локальный запуск
```bash
# Любой статический сервер, например:
npx serve /path/to/quiz-editor
# или
python3 -m http.server 8080 --directory /path/to/quiz-editor
```
Открыть `http://localhost:8080`

> Прямое открытие `index.html` через `file://` работает для редактирования, но `localStorage` может быть ограничен в некоторых браузерах.

### Вариант 3: Любой статический хостинг
Загрузить `index.html`, `style.css`, `app.js` в корень — редактор заработает немедленно.
