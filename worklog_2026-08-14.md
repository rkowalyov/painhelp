# Отчет по работе за 2026-08-14

## Кратко
Сегодня внесены изменения в движок квиза, превью в конструкторе и структуру сценариев.
Ключевой результат: квиз стал поддерживать ранний выход по условию score = 0 и произвольное количество уровней скоринга.

## Что сделано

### 1) Ранний выход в финал при score = 0
- Обновлена логика прохождения вопросов в основном квизе.
- Если у выбранного варианта score равен 0, квиз сразу переходит к финальному этапу (экран email), пропуская оставшиеся вопросы.
- Та же логика добавлена в превью-движок конструктора, чтобы поведение в редакторе совпадало с боевым.

### 2) Переход от 3 фиксированных уровней к динамическому скорингу
- Убрана жесткая привязка к low/medium/high.
- Добавлен универсальный расчет уровня результата на основе отсортированных порогов max.
- Поддерживается произвольное число уровней (включая 7+).
- Сохранена обратная совместимость: старые JSON с тремя уровнями продолжают корректно обрабатываться.

### 3) Обновление конструктора квизов
- Вкладка Скоринг переведена на динамические карточки уровней.
- Добавлены действия:
  - Добавить уровень
  - Удалить уровень
- Экспорт JSON из конструктора теперь собирает все уровни, а не только три фиксированных.
- Превью результата в конструкторе обновлено под динамические уровни.

### 4) Подготовлены сценарии для A/B/C
Созданы отдельные файлы сценариев с суффиксом _2608_001:
- scenarios/pain-v1_baseline_2608_001.json
- scenarios/pain-v1_strict_2608_001.json
- scenarios/pain-v1_growth_2608_001.json

Все три сценария содержат:
- одинаковый набор вопросов,
- одинаковые CRM-поля,
- 7 уровней скоринга,
- различия в порогах и текстах по стратегии.

## Подход к сценариям

### Цель
Разделить продуктовые гипотезы по интерпретации баллов, не меняя ядро квиза и не смешивая аналитику.

### Принципы
1. Один и тот же опрос и шкала баллов.
2. Разные пороги и тексты результатов как отдельные сценарии.
3. Отдельный source_label для трекинга в CRM и аналитике.
4. Версионирование в имени файла для управляемых итераций.

### Варианты

#### Baseline
- Контрольный сценарий.
- Нужен как точка сравнения для A/B/C.
- Используется для оценки изменений strict/growth без сдвига по вопросам.

#### Strict (медицински строгий)
- Более ранний переход в высокие уровни риска.
- Приоритет: не пропускать потенциально сложные случаи.
- Подходит, если главная цель безопасность маршрутизации и раннее обращение.

#### Growth (маркетинговый)
- Более мягкий переход в верхние уровни.
- Приоритет: ниже тревожность, выше вовлечение в контент и диалог.
- Подходит, если основная цель расширение воронки и конверсия в следующий шаг.

### Схема версионирования
- Формат: _2608_001
- 2608: август 2026
- 001: версия внутри месяца

### Как использовать
- Подключение сценария через параметр quiz:
  - ?quiz=pain-v1_baseline_2608_001
  - ?quiz=pain-v1_strict_2608_001
  - ?quiz=pain-v1_growth_2608_001

### Что сравнивать в A/B/C
1. Распределение пользователей по уровням.
2. Конверсия в целевые действия из каждого уровня.
3. Доля ранних выходов по score = 0.
4. Качество лидов по source_label и по варианту сценария.

## Примечание по загрузке конструктора
По умолчанию конструктор загружает встроенный DEFAULT_JSON,
если нет входящих данных через load и нет сохраненного состояния в localStorage.
